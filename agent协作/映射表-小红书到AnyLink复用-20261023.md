# 复用/迁移映射表：xhs-curator → AnyLink2Note

## 0. 复用判定图例

| 标记 | 含义 |
|---|---|
| 🟢 **可直接调用** | 以「稳定入口」调用（子进程 CLI / HTTP / 读契约文件），源码不复制 |
| 🟡 **需适配** | 逻辑可搬，但常量（目录、标识、平台判定）或数据结构必须改 |
| 🔴 **不适合复用** | 与 AnyLink 场景冲突（多平台、逐 P 身份、登录前提不同），各自实现 |

**防漂移总原则**（先于细节）：**优先稳定入口调用，不复制源码、不抽公共框架**。
- 入口形态：CLI（`python <repo>/xxx.py --classify ...`）+ HTTP（工作台 API）+ 文件契约（raw.json / stats 契约）
- 若必须复制（判定 🟡🔴 的部分），复制点标注"源版本 commit + 同步条件"，AnyLink 侧**不承诺跟随升级**

## 6. 已知差异对映射的影响（派工信 §B.3 逐条应答）

| 差异 | 对复用的影响 |
|---|---|
| AnyLink 多平台、B 站单视频也可能需登录 | classify 的 platform 维度要多一层（平台 × 输入类型）；「单篇免登录」不能作为通例——登录决策必须由平台能力矩阵驱动，不能沿用小红书的"单篇一律匿名" |
| 内容身份需逐 P（平台/BV/CID） | 任务记录与 stats 的 note_id 语义 → `content_key`（平台+作品+分P）；断点/去重/续跑全链路按 content_key，不能按 URL |
| 安装标识/解释器/profile/运行目录 | **严禁**指向 xhs-curator：marker 名、skill 目录名、`browser_profile/`、`runtime/jobs/` 全部独立；解释器可共用同一 venv（依赖重合度高），但 marker 记录各自 |
| 单篇快读无需工作台 | 结果卡/进度条只服务多 P 场景；单篇走"直接产物 + 对话告知"，不要引入工作台依赖 |
| 多 P 停止以当前 P 为边界 | stopped 语义 = 当前 P 完成即停；统计需含 `parts_total/parts_done`，验收时要能证明"已完成 P 可独立访问" |
