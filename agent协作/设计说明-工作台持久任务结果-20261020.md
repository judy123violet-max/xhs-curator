# 设计说明：工作台持久任务结果与完成引导

## 1. 目标

抓取/搜索单任务结束后，其结果（成功/失败/跳过统计、失败原因、下一步引导）**持久保存**：刷新页面、错过 Toast、重启工作台服务后，用户回来仍能看到准确结果与下一步；一次性 Toast 不再是唯一通知。

## 2. 数据设计

### 2.1 存储位置

`<仓库>/runtime/jobs/`（新增 `.gitignore: runtime/`）：
- `<job_id>.json` —— 任务记录（job_id = `YYYYMMDD-HHMMSS-<type>`）
- `<job_id>.log` —— 该任务完整 stdout 日志（运行中由 pump 边收边写）

### 2.2 任务记录 schema

```json
{
  "job_id": "20261020-010900-fetch",
  "type": "fetch | one | search",
  "with_comments": true,
  "only_ids": [],                     // 仅重试失败项时的目标 note_id
  "selected": 25,                     // 启动时选中/目标数量（fetch=selection 数，one=1）
  "started_at": "2026-10-20T01:10:00",
  "ended_at": "",
  "exit_code": null,
  "status": "running | done | partial | failed",
  "confirmed": false,                 // 用户在结果卡点「知道了」后置 true
  "stats": {                          // 抓取脚本经环境变量回写的本轮统计；缺失=null
    "planned": 25, "ok": 24, "failed": 1, "skipped": 3,
    "failures": [{"note_id": "...", "title": "...", "error": "goto: Timeout..."}]
  }
}
```

### 2.3 统计来源与 partial 判定

- 抓取脚本（fetch/one）结束时，把**本轮**统计写入环境变量 `XHS_JOB_STATS` 指向的路径：
  `planned = len(todo)`、`ok = manifest 中本轮 ok=true 数`、`failed = ok 之外的失败数（含 error 摘要）`、
  `skipped = 清单数 − todo 数`（断点跳过）。纯函数 `job_stats_payload()`，可单测。
- picker 进程结束后读取该文件合并进任务记录；**子进程异常终止拿不到统计时，fetch/one 直接判 failed**
  （而不是笼统 done）——满足"不只以 exit=0 判断"。
- 状态判定 `compute_job_status()`：
  - search：exit==0 → done，否则 failed
  - fetch/one：无 stats → failed；ok==planned 且 planned>0 → done；0<ok<planned → **partial**；ok==0 → failed

## 3. API

| 路由 | 方法 | 作用 |
|---|---|---|
| `/api/jobs` | GET | 最近 20 条任务记录（倒序）+ 当前运行状态；服务重启后仍从文件读取 |
| `/api/jobs/<id>/log` | GET | 该任务日志文件内容（供"查看运行日志"） |
| `/api/jobs/<id>/confirm` | POST | 结果卡点「知道了」→ confirmed=true |
| `/api/retry_failed` | POST `{job_id}` | 取该任务失败条目 note_id 列表 → 以 `--only-ids` 启动新 fetch 任务 |

**勾选主权**：`--only-ids` 只从 selection.json 已选条目里过滤，selection.json 本身不被改写；
「仅重试失败项」由用户在结果卡上主动点击触发，属于用户决策，不违反 SKILL 硬性规则 8。

## 4. 抓取脚本改动（xhs_fetch_selected.py）

- 新增 `--only-ids id1,id2`：只抓这些 note_id（在 selection 清单内过滤，断点规则照旧）
- 新增 `job_stats_payload()` 纯函数；结束时若环境变量 `XHS_JOB_STATS` 存在则写统计 JSON

## 5. 工作台 UI（结果卡）

- 页面加载/刷新时拉 `/api/jobs`：最近一条 `confirmed=false` 且非 running 的任务 → 在清单上方渲染**持久结果卡**
- done 卡：`✓ 上次抓取完成：成功 N · 跳过 M` + 按钮「查看已抓笔记」「知道了」
  + 下一步引导文案："回到 Agent 对话说『导入 Obsidian』即可入库"
  （OCR/导出是 AI 侧动作，工作台不自动执行——按钮做引导不做越权执行，请在复验时裁定此取舍）
- partial 卡：`⚠ 部分完成：成功 N · 失败 F · 跳过 M` + 「查看失败原因」（展开 failures 列表）+「仅重试失败项」+「知道了」
- failed 卡：`✗ 抓取失败` + 错误摘要 +「知道了」（若有失败条目也给「仅重试失败项」）
- 运行中信息仍走现有实时日志面板（定位=运行中）；结束后以结果卡为权威
- 不做对话自动通知（按信中第 6 条，留后续任务）

## 6. 测试用例（tests/test_job_record.py，先行提交）

1. `job_stats_payload()`：planned/ok/failed/skipped/failures 计算正确（含 error 缺省）
2. `compute_job_status()`：done/partial/failed/无统计 crashed 判定矩阵
3. 任务记录持久化 roundtrip（写→读→列表倒序）+ confirm 落盘
4. `build_cmd` 支持 `--only-ids`；search 不受影响
5. 重启可追溯 = `/api/jobs` 数据源为文件而非内存（直接验证 load_jobs）
6. 勾选主权：retry 相关函数不写 selection.json（仅读）

## 7. 验收对照

- 刷新后仍见准确统计与下一步 → 结果卡从文件渲染 ✓
- 人为失败 → partial 卡 + 失败可见 + 仅重试失败项 ✓
- 服务重启后可追溯 → /api/jobs 读文件 ✓
- 不碰勾选主权、不自动 OCR/导出 → §3/§5 ✓
