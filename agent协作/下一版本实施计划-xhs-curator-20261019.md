- 来源：雅旭整理并确认的 `用户路线流程图-xhs-curator-可编辑-20261019.drawio`

## 一、目标

把单篇小红书链接的默认交付改为：匿名抓取成功后，**直接生成并提供可下载的 Markdown 文稿**。只有用户明确说“导入 Obsidian”时，才执行入库；整个过程不应重新访问小红书、不应要求用户重新登录。

主页批量、关键词搜索、博主评论继续属于引擎 B 的登录态工作台能力，不与单篇匿名路线混用。

## 二、用户路线（本次定稿）

```text
单篇笔记链接
  → 引擎 A（匿名、免登录、不抓评论、不询问）
  → 成功：抓取正文、原图；视频取得官方字幕或本地 Whisper 转写
  → 图文图片经过逐图 OCR 价值闸门
  → 生成并提供可下载的 .md 文稿（含本地图片/附件引用）
  → 弱提示：如需存入 Obsidian，请说“导入 Obsidian”
  → 用户明确请求时：按来源路由入库
       - 引擎 A：to_downloads.py 转为统一 downloads 契约，再 xhs_export_md.py
       - 引擎 B：直接 xhs_export_md.py
  → Obsidian 库与 00 索引

匿名抓取失败、风控降级或分享链接失效时，如实说明原因；仅在此时建议登录态重抓。
```

视频封面图不属于本次版本输出范围：默认留在抓取留档，不导出、不进入 OCR 价值闸门。

## 三、实施项

### 1. 让引擎 A 的 Markdown 成为正式交付物

- 在单篇成功路径生成持久 `.md` 文件，而不只是会话内临场文本。
- 文稿应包含标题、正文、来源、作者/时间（可获得时）、图文图片引用；视频包含字幕或转写及来源说明。
- 原图和其他附件必须与 Markdown 一起保留；文稿中的引用在下载后仍可访问。
- 同时保留本次引擎 A 原料包，供用户之后选择入库时复用。

### 2. 打通“稍后导入 Obsidian”，不得重抓

- 用户明确要求导入时，判定本次数据来源。
- 来源为引擎 A：运行已有 `skill/scripts/to_downloads.py`，仅转换本地 `metadata.json`、图片、字幕/转写等已有数据；随后调用 `xhs_export_md.py`。
- 来源为引擎 B：保留现有 `downloads/` 直接导出路径。
- 不得在引擎 A 成功后，为入库而再次请求小红书、再次下载原图或要求登录。
- 需补齐 `to_downloads.py` 对无官方字幕视频 `transcript.txt` 的转换/导出支持；导出结果不得丢失可用的本地转写。

### 3. 对齐 OCR 与视频边界

- 图文笔记的图片执行现有逐图 OCR 价值闸门，保留 `ocr_status.json` 与必要时的 `ocr.md`。
- 视频封面默认只留档；不进入 OCR，也不出现在默认交付 Markdown 中。
- Whisper 不可用或转写失败时，不得让正文 Markdown 失败；应保留正文并清楚标注“未取得字幕/转写”。

### 4. 流程图与文档勘误

- 更新仓库 `README.md`、`README_EN.md`、`skill/README.md`、`skill/SKILL.md`，删除“单篇要入 Obsidian 必须登录态重抓”的表述。
- Draw.io 图中将“有可行方案？→ 是”连接到“按可行方式自行处理”，并将所有 OCR 分支与来源判断分支绑定到实际节点，避免仅使用绝对坐标导致移动图形后脱线。
- 图中“如需存入 Obsidian”的文字保持弱提示，不作为每次交付后的阻断式询问。

## 四、验收标准

1. 单篇图文在匿名抓取成功后，能获得可下载 Markdown 及本地图片/附件；不登录、不抓评论。
2. 对同一份已成功的引擎 A 原料包执行“导入 Obsidian”，过程中没有第二次小红书网络抓取；转换后由统一导出器生成 frontmatter、附件和 `00 索引`。
3. 单篇视频分别覆盖“有官方字幕”和“无字幕但本地转写”两种情形；后者的转写能进入最终 Markdown/Obsidian 成果。
4. 引擎 A 失败/风控降级时，仅此路径显示登录态重抓建议；成功路径不出现登录要求。
5. 主页链接仍仅在工作台内询问是否保留博主评论；关键词搜索仅为工作台内嵌能力。
6. 既有测试通过，并新增至少以下自动化测试：
   - A 原料包转换后可被导出器读取；
   - `transcript.txt` 不丢失；
   - A 入库路径不调用抓取函数；
   - 视频默认不输出封面图。
