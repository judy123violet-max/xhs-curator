# P0-B 验证方案：对话桥接可行性 Spike（修订版 v2）

## 0. 要验证的两个方向

| 方向 | 问题 | 难度 |
|---|---|---|
| **回传**（后台 → 对话） | 任务结束时，能否让**发起它的同一对话**"知道"结果？ | 难——WorkBuddy 无外部进程唤醒对话的推送通道 |
| **控制**（对话 → 后台） | 用户在对话里说"停止/只抓 N 篇"，能否安全转成**指定 job_id**的任务控制？ | 中——AI 可达本机 API，但现接口是全局控制，无 job_id 定位与来源绑定 |

## 1. 回传方向：三候选通道（按二次审阅收紧定性）

### 通道 R1：Agent Mail（终态邮件）——定性降级为「外部通知候选」

- 机制：任务终态时由轻量监控脚本发一封含 `job_id`/`status`/统计的邮件到 zouyaxu@agent.qq.com
- **二次审阅收紧**：邮件进入的是收件箱，**不等于"原发起对话已知道结果"**——它只是外部通知候选：
  - 不能作为「同一对话回传」的成功证据
  - 不得据此承诺"用户回到对话时 AI 一定立即知道"（承诺口径改为：**回到对话时可查**——AI 从 runtime/jobs 追溯）
- 验证步骤（保留，只验证"邮件可达"这一事实）：fake 慢任务 → 终态触发 notify.py → 断言收件箱收到含 job_id/status 的邮件
- 判定：**候选外部通知**（可用/不可用），不计入桥接通过证据

### 通道 R2：WorkBuddy 定时任务轮询——验收必须含「同一对话交付」

- 机制：抓取开始时建一次性 automation，定时检查 `/api/jobs` 状态并汇报
- **二次审阅收紧**：仅验证 localhost 可达**不够**。完整验收 =
  1. automation 执行环境能访问本机 127.0.0.1:8788（前置，待实测）
  2. **结果必须交付到发起任务的同一对话**——另一个任务/窗口里出现的输出**不算桥接通过**
  3. 若 automation 无法定向到原对话 → R2 标记为「不可行（当前平台能力）」
- 判定：三条件全过才算可行；任一失败 → R2 否决，回传方向整体标为「当前不可行，仅工作台可查」

### 通道 R3：桌面通知（降级兜底）

- 纯本地 Toast，不经过对话。可行（P2 范围），提醒用户"回来看"，不构成回传证据

### 回传总结判定（收紧后）

- 「AI 主动实时推送」不可行
- R1 = 外部通知候选；R2 = 待实测（含同一对话交付判定）；R3 = 兜底提醒
- **无论如何：工作台独立可用 + 终态落盘可查询**（V4 必测），用户回对话时 AI 从 runtime/jobs 精确追溯

## 2. 控制方向：V3 收紧（二次审阅意见 3/4）

### 现状承认

现有 `POST /job/stop` 是**全局当前进程控制**：无 job_id 定位参数、无对话与 job_id 的安全绑定、多窗口场景可能误停别人的任务。"AI 能调这个接口"**不构成 V3 通过**。

### 收紧后的 V3 验收（前置依赖：P0-A 提供 job_id 级控制接口）

| # | 验收点 |
|---|---|
| 1 | 控制接口支持**按 job_id 定位**（不是全局当前进程） |
| 2 | **发起来源校验**：执行控制前核对发起方与 job 的绑定关系；存在歧义（多窗口/来源不明）时必须向用户确认，不得盲停 |
| 3 | 命令执行后任务状态**正确转为 stopped**，已完成篇保留 |
| 4 | 修复引导：解释器/服务异常时提示重跑 install.py（沿用 P0-4 机制） |

### 「只抓 N 篇」标注（二次审阅意见 4）

完整验证**依赖 P0-A 先提供协作式 limit 控制**。P0-A 之前，P0-B 只验证当前停止链路（V3 收紧版）；"只抓 N 篇/继续"标记为 **待 P0-A**，不写成已验证能力。

## 3. 降级行为（V4 必测，二次审阅意见 5 保留）

R1/R2/R3 全部失败时，必须验证：

- 工作台独立可用（进度、停止、结果卡不依赖任何桥接）
- 终态落盘可查询（runtime/jobs 记录完整）
- 不伪造已通知（绝不显示/声称"已在对话告知"）

## 4. Spike 执行清单（修订版）

| 编号 | 内容 | 产出 | 判定 |
|---|---|---|---|
| V1 | 终态邮件可达性 | 邮件 + job_id/status 比对 | **外部通知候选**（不计入桥接证据） |
| V2 | automation localhost 可达 + **同一对话交付** | automation 对话输出 + 交付对象核对 | 三条件全过才可行 |
| V3 | **指定 job_id** 的停止控制（前置：P0-A 接口） | 命令序列 + status=stopped 证据 + 来源校验/歧义确认行为 | 按收紧验收表 |
| V4 | 全通道失败降级 | 任务完成、状态可查、不伪造已通知的证据 | 必须满足 |

## 5. 安全边界（贯穿，不变）

- 发起对话的标识（若有）不写入公开仓库/任务日志/导出物
- 监控/控制脚本只读 /api/job 与本地文件，不碰登录态与账号数据
- Spike 产物只进 `agent协作/`，不入生产代码
