# xhs-curator：长任务状态与中断协议

## 0. 本轮要解决什么

当前工作台能在本机后台抓取，但 AI 启动工作台后即结束本轮对话；用户既不知道 AI 是否还在等，也无法在对话中可靠地说“停止”或“只抓两篇”。

本规格把采集定义为一个**可观察、可控制、可恢复的长任务**。用户只需选择笔记、开始、查看进度；需要改变主意时，可以在工作台或对话中下达控制命令。任务结果要诚实区分“素材已抓到”和“Markdown 已生成”。

## 1. 已核实的现状与约束

### 已有能力（可复用）

- `xhs_picker_server.py` 已有任务记录、`job_id`、`GET /api/job`、`GET /api/jobs`、任务日志和浏览器页内轮询。
- 工作台已有“停止”入口，但现状是 `p.terminate()` 硬终止。
- 每篇抓取脚本能逐篇输出日志；任务结束后可写出成功/失败统计。

### 现有缺口（不能用文案掩盖）

- 没有结构化实时进度：只有日志文本，无法可靠画进度条或供 AI 汇报。
- 硬终止可能使任务被标记为失败，缺少“用户停止、已保留 N 篇”的正式终态。
- 没有“抓到第 N 篇后停止”的协作式控制接口。
- 采集服务不持有 WorkBuddy 对话 ID，也没有消息回调能力；它不能自行向发起它的 AI 对话推送进度。
- 批量抓取完成目前是素材包完成，不应假称“Markdown 已导出”。OCR 与 Markdown 导出是后续处理阶段。

## 2. 产品边界

### 本阶段承诺

- 工作台对当前任务展示清晰、持续、可中断的进度与结果。
- 当前页面只展示本页发起的任务；新窗口不串出历史任务卡。
- 用户可以在工作台停止任务；在对话发出的停止/改上限命令，只有在“对话桥接验证通过”后才承诺可用。
- 完成后明确告知保存位置、当前产物类型、以及进入 Obsidian 的下一步。

### 本阶段不承诺

- 不把“复制一段提示词”伪装成“继续 OCR/导出”。
- 不未经确认直接执行 OCR 或导入 Obsidian；这涉及模型成本、目标库及可能的覆盖行为。
- 不保证 AI 自动推送任务完成消息，除非 P0-B 的桥接实验证明可行。
- 不让 AI 代替用户改勾选清单；用户的运行时控制只作用于尚未开始的任务。

## 3. 用户可见状态机

```text
待选笔记
  └─ 开始抓取 → 抓取中
                     ├─ 用户停止 → 停止中 → 已停止（部分完成）
                     ├─ 单篇失败但任务未结束 → 抓取中
                     └─ 全部目标处理完 → 素材抓取完成
                                              ├─ 用户选择“生成 Markdown” → Markdown 整理中
                                              │                                  ├─ 已生成 Markdown
                                              │                                  └─ 处理失败 / 已停止
                                              └─ 暂不整理 → 等待用户决定

已生成 Markdown
  └─ 用户在 Agent 对话确认导入 → 导入 Obsidian 中 → 已入库 / 导入失败
```

**核心原则：** “素材抓取完成”“Markdown 已生成”“已导入 Obsidian”是三种不同状态，界面和对话不得混称。

## 4. P0：先实现并验收的最小闭环

### P0-A：工作台内的结构化进度与温和停止

**目标：** 用户不依赖 AI 对话，也能知道当前任务在做什么、已完成多少，并安全停止。

任务记录增加运行期字段（示意）：

```json
{
  "stage": "fetching",
  "total": 25,
  "completed": 7,
  "success": 6,
  "failed": 1,
  "skipped": 0,
  "current_note_title": "正在抓取的笔记标题",
  "control": {"stop_requested": false, "limit": null}
}
```

工作台顶部常驻：

- 进度条：`已处理 7 / 25`，并标示成功、失败、跳过数。
- 当前条目：`正在处理：……`；没有进行中条目时如实显示“正在汇总”。
- 主操作：`停止本次抓取`，点击后变为“正在停止，已完成内容会保留”。
- 底部日志仍保留，但不再承担唯一进度告知职责。

停止必须改为**协作式停止**：抓取循环每完成一篇、开始下一篇前读取控制状态；收到停止请求后不再启动下一篇，写入完整统计并落为 `stopped`（不是 `failed`）。如当前篇正在下载，允许在安全边界结束或中止该篇，但不能损坏已完成目录。

**验收：**

1. 选 5 篇后，顶部能实时显示 0/5 → 1/5 等结构化进度。
2. 在 2/5 时点停止，最终状态为“已停止：已完成 2/5”，两篇文件可打开，未开始三篇未抓取。
3. 停止、刷新页面、重启工作台后，仍能读到该任务真实状态与统计。

### P0-B：对话桥接可行性 Spike（只验证，不承诺上线）

**目标：** 判断 WorkBuddy 是否能把后台 `job_id` 的状态回传给发起该任务的同一对话，并在用户新消息到来时转交控制命令。

必须验证的最小链路：

1. 启动工作台任务时，保存发起对话的可用标识（不得写入公开仓库或任务日志）。
2. 一个受控监控器以有限频率读取 `/api/job` 或按 `job_id` 查询状态。
3. 状态从 `fetching` 变成 `done/stopped/partial/failed` 时，能在**同一对话**输出一条结果消息。
4. 用户发送“停止”后，监控器能把命令转为该 `job_id` 的控制请求；用户发送“只抓 2 篇”后，能校验并设置安全上限。
5. 关闭/重启对话、监控器异常、服务重启时的降级行为：工作台仍独立可用；不能发送消息时不丢任务，不伪造已通知。

**验收：** 交付可复现的最小验证记录，而不是口头声称“平台支持”。若任一项不能证明，则 P0-B 标记为“不具备”，P1 不得把自动对话汇报画成已实现。

### P0-C：当前任务结果卡与真实后续动作

- 当前页发起的抓取完成/停止/部分失败后，显示该 `job_id` 的持久结果卡。
- 新页面不显示其他页面历史任务的结果卡。
- 成功卡的“查看已抓笔记”“打开保存位置”可直接执行。
- 结果卡必须写清：`素材已保存至 …`；不得写“Markdown 已生成”，除非 P1-A 已实际完成。
- “导入 Obsidian”只能显示为下一阶段：`如需入库，请在当前 Agent 对话发送“导入 Obsidian”。` 不得用假执行按钮替代。

## 5. P1：Markdown 生成与对话控制

### P1-A：把 Markdown 生成做成独立、真实的任务阶段

在用户选择“生成 Markdown”或产品明确批准自动生成后，创建新的处理任务，不与抓取阶段混写。

- 显示阶段：`正在整理 Markdown（含 OCR 判断）`。
- OCR 成本闸门按既定规则执行；跳过 OCR 时保留原图并在结果中说明。
- 成功后显示 Markdown 文件数量、保存路径、`查看 Markdown`。
- 取消时保留已完成 Markdown；未完成笔记可续跑，不重抓。
- OCR 失败、导出失败和抓取失败必须分别可辨。

**为什么是 P1：** 需要明确多模态模型配置、成本、耗时和每篇重跑幂等性，不能趁“抓取体验优化”偷渡上线。

### P1-B：对话运行时控制（以 P0-B 验证通过为前提）

用户在对话中可说：

- `停止抓取` / `先停一下`
- `只抓 2 篇`
- `继续`
- `进度怎么样`

语义规则：

| 命令 | 行为 |
|---|---|
| 停止 | 设置 `stop_requested=true`，不再开始下一篇；保留已有成果 |
| 只抓 N 篇，已完成 < N | 设置 `limit=N`，到第 N 篇后协作式停止 |
| 只抓 N 篇，已完成 = N | 立即协作式停止 |
| 只抓 N 篇，已完成 > N | 不回滚，告知已完成数并停止后续 |
| 继续 | 仅对已停止任务，需确认剩余清单仍有效后恢复 |
| 进度怎么样 | 返回结构化进度，不堆整段日志 |

注意：这些命令不改 `selection.json`，只控制当前 `job_id` 尚未开始的工作。

## 6. P2：体验增强（不阻塞 P0/P1）

- 预计剩余时间和速率估算。
- 单篇级暂停/跳过/重试。
- 系统通知或桌面通知。
- 任务历史筛选与导出报告。
- OCR 队列的预算预估与用户确认。

## 7. 原型必须回答的问题

WorkBuddy 的原型稿必须包含四个完整页面/状态：

1. 抓取中：顶部进度、当前标题、成功/失败/跳过、停止按钮、底部日志。
2. 用户在 2/5 停止：停止中与最终“已停止 2/5”，并显示保留位置与继续入口。
3. 部分完成：明确哪些成功、哪些失败；不与其他窗口历史任务混淆。
4. 素材抓取完成：保存位置、查看已抓笔记、下一阶段 Markdown 的真实状态；不要出现假装执行 OCR 的按钮。

若 P0-B 尚未验证，原型里的 AI 对话自动进度/主动通知必须标注“候选，待平台验证”，不能用成品样式暗示已可用。
