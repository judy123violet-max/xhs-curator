# P0-B Spike 验证记录：对话桥接可行性

## 执行摘要（一句话结论）

**实时推送不可行；"异步邮件回执"技术上可通但产品不采用**（雅旭 2026-10-23 决断）——定时任务环境可访问本机工作台 API 并通过 Agent Mail 回传结果（V2 实证），但输出落在独立会话而非原对话，需用户回到对话触发 AI 读信；对本地工具属绕路，完成感知应以工作台持久结果卡为准。工作台独立可用性不受影响（V4 通过）。

## V1：后台脚本直发邮件 —— 不可行（实证）

- 尝试：后台 Python 脚本直接发 agentmail
- 结果：agentmail 是 MCP 工具，**仅在 AI 会话内可用**；后台脚本无 SMTP 服务器/凭证（本机无任何 SMTP 配置，已盘点）
- 判定：**R1 自动通道不可行**。变体：AI 在对话中代发（无增量价值，等价于 AI 汇报）

## V2：定时任务探针 —— 部分可行（实证，三条件两过一不过）

一次性 automation（22:10 触发）执行：curl 本机 8788 → agentmail 回传。

| 条件 | 结果 |
|---|---|
| ① automation 环境可访问本机 127.0.0.1:8788 | ✅ curl Exit 0，返回真实任务数据（json 完整） |
| ② automation 能通过邮件回传结果 | ✅ 收件箱收到「P0B-SPIKE-V2 探针回执」（发件 zouyaxu@，收件 zouyaxu@，22:11:25） |
| ③ 结果交付到**发起任务的同一对话** | ❌ 输出落在 automation 独立会话 + 邮件收件箱——按收紧口径**不算桥接通过** |

**判定：R2 部分可行**。「同一对话实时交付」当前平台能力不支持；但「任务终态 → 邮件回执 → 用户回任意对话说『看看信』→ AI 读信获知结果」这条**异步链路端到端走通**（发：automation 实证；读：本会话实证）。

## V3：指定 job_id 的停止控制 —— 链路可行，需 P0-A+ 补接口（代码实证）

- 现状实证：`POST /job/stop` 收到 body `{"job_id": "完全不相干的job_id-12345"}` 时**完全忽略该字段**，按全局当前进程语义响应（实测返回"当前没有运行中的任务"）——多窗口误停风险实锤
- 协作式停止本身已被 P0-A 验证（tests/test_cooperative_stop.py：5 篇 2/5 停止 → stopped/ok=2/user_stopped）
- **缺口**：控制接口缺 job_id 定位参数与发起来源绑定 → 列为 **P0-A+ 小增量建议**（/job/control 增加 job_id 校验），不在 Spike 内实施
- 判定：**单任务场景可行（已验证）；多窗口安全需 P0-A+ 补接口后复验**

## V4：全通道失败降级 —— 通过（既有证据）

- 工作台独立可用：进度/停止/结果卡不依赖任何桥接（tests/test_cooperative_stop.py + 前端实现）
- 终态落盘可查：runtime/jobs 记录完整（/api/jobs 实测返回历史任务，含 10-21 数据）
- 不伪造已通知：无任何自动通知代码路径存在

## 综合结论与建议

| 能力 | 判定 | 建议 |
|---|---|---|
| AI 主动实时推送 | ❌ 不可行 | P1-B 中删除该承诺 |
| 异步邮件回执（自动化发 + AI 读） | ✅ 技术可行 / ❌ **产品不采用**（雅旭 2026-10-23） | **不实施**。完成感知 = 工作台持久结果卡 + 回对话问 AI 查 runtime/jobs；邮件通道仅作为技术验证存档，不得再作为 P1-B 方案 |
| 对话命令控制（停止/只抓 N） | ⚠ 单任务可行，多窗口需补 job_id 接口 | P0-A+ 小增量（/job/control 带 job_id 校验），随下轮实施 |
| 工作台独立闭环 | ✅ 始终可用 | 已是现状 |

## 产品决断记录

- **2026-10-23 雅旭拍板**：邮件通知**不进入产品形态**——"抓小红书的本地工具不需要邮件"。R1/R2 的邮件链路留作技术验证存档（证明平台无推送通道可用），P1-B 不再以邮件为方案；完成感知以工作台持久结果卡为准，用户回对话时 AI 从 runtime/jobs 查询补充。
