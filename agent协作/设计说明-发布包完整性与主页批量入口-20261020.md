# 设计说明：发布包完整性与主页批量入口可安装性

## 一、问题复述（与 Codex 核对一致）

- 对外 Skill 发布单元 `skill/` 只含 SKILL.md + fetch_xhs_note.py + to_downloads.py
- SKILL.md/README 却要求使用仓库根目录的批量脚本（`../xhs_fetch_selected.py` 等）
- 用户仅装 `skill/` → 上级目录不存在 → **主页批量能力不可执行**
- 违反"对用户只有一个完整入口 xhs-curator，内部按链接类型路由"的产品口径

## 二、发布结构选项与取舍

### 选项 A：自包含大包（把全部脚本搬进 skill/）

| 维度 | 评价 |
|---|---|
| 用户安装 | 拷一个目录，一步到位 |
| 一个入口 | ✓ |
| 维护性 | ✗ **最差**：根目录与 skill/ 双份同源代码，每次改动都要双向同步——今天刚处理过"用户级副本落后两个版本"的同构问题，双份维护必然再次漂移 |
| 改造成本 | 大（全部脚本搬家 + 所有相对路径重写 + 测试全改） |

### 选项 B：仓库即安装包 + 轻入口 Skill（**推荐**）

安装 = `git clone` 仓库 + 跑一条 `install.py`。install 把 `skill/` 复制进用户技能目录，并写入 **marker 文件**（记录仓库绝对路径）。Skill 运行时按优先级定位仓库根：

```text
① 环境变量 XHS_CURATOR_HOME
② skill 同级 marker 文件 .xhs-curator-root（install 写入仓库绝对路径）
③ 向上逐级探测（开发场景：skill/ 就在仓库里）
④ 全部失败 → 输出可操作的安装引导（见 §四.3）
```

| 维度 | 评价 |
|---|---|
| 用户安装 | clone + 一条命令（README 三步：clone → install → pip） |
| 一个入口 | ✓ 单篇/主页/批量全部可用 |
| 维护性 | ✓ **单一事实源**：代码只在仓库根，skill/ 只是 SKILL.md + 单篇快读脚本 + install 入口，永不漂移 |
| 改造成本 | 中（install.py 新写；SKILL.md 路径逻辑重写；批量脚本零改动） |

### 选项 C：两级安装（单篇自包含 + 批量另装完整仓库）

单篇开箱即用；主页链接触发时检测批量组件，缺失则给安装引导。
**否决理由**：保留两级体验，与 Codex"只有一个完整入口"的口径直接冲突；只是给断腿包贴了张说明书。

**推荐 B**。核心收益：单一事实源消灭双份同步（今天 displayName 一役已实锤双份维护的漂移风险），且批量脚本零改动、风险最小。

## 三、统一入口路由（硬判定，不靠模型软匹配）

### 3.1 链接分类器（代码层，复用已有 resolve_url/parse_note_url）

`fetch_xhs_note.py` 新增 `--classify "<链接或分享文字>"` 模式，输出 JSON：

```json
{"link_type": "single|profile|invalid", "resolved_url": "...", "note_id": "..."}
```

判定规则（先 resolve 短链，再看 URL 形态）：

| link_type | 判定 |
|---|---|
| `single` | `/explore/{24位id}`、`/discovery/item/{id}`、`/item/{id}`，或短链解析后命中上述形态 |
| `profile` | `/user/profile/{user_id}`、手机端主页分享文字解析出的主页链接、短链解析后指向 profile |
| `invalid` | 无法解析 / 非 xiaohongshu 域 |

### 3.2 SKILL.md 路由规则（AI 只执行分类结果，不猜）

```text
用户发来链接/分享文字
  → 第一步必跑: fetch_xhs_note.py --classify "<原文>"
  → single   → 引擎 A（匿名快读，单篇 .md 交付）
  → profile  → 定位仓库根（§二.B 优先级链）
               ├─ 找到   → 启动 xhs_picker_server.py 工作台（登录态批量）
               └─ 找不到 → 主页能力安装引导（§四.3），绝不说"链接无效"
  → invalid  → 如实说明无法识别，请用户重新分享
```

### 3.3 关键：手机端主页分享文字

小红书 App"分享主页"产出的是口播文字+短链，短链事前看不出指向。**分类器必须先 resolve 再分类**（resolve_url 已具备），AI 不许按文字内容猜。

## 四、用户体验兜底（Codex 要求 §3）

1. **主页 ≠ 无效链接**：classify=profile 永远是"有效链接，需要完整安装/登录态"，提示语固定结构："这是博主主页链接，批量采集需要登录态工作台……"
2. **安装引导可操作**：缺失组件时输出三步（git clone 仓库地址 → `python install.py` → 重启对话再试），每步带完整命令
3. **依赖前置提示**：install.py 检测 python 版本 / pip 依赖 / Chrome，缺什么报什么，附安装命令
